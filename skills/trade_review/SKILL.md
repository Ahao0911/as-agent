# 盘后复盘技能（trade_review）
- 触发词：盘后复盘、今日复盘、简单复盘、深度复盘、复盘并推送
- 功能：完整盘后复盘闭环——盘前计划验证 → 市场环境 → 指标战法复盘 → 个人操作复盘 → 行情多维 → 明日情景推演 → 落盘
- 闭环位置：读取今日盘前提示做"盘前计划验证" → 生成明日推演落盘（次日盘前自动读取）

## 启动流程
1. 检查当日交易记录（utils/trade_journal.py today）
2. 无记录：只问一次「今天有操作吗？请按格式填写：股票名称或代码、买入或卖出、数量、成交均价、成交时间、操作理由、原计划止损或止盈。没有操作回复"无操作"」
   - ⚠ ETF数量单位是「份」不是「手」！记录时用 --unit 份（如 588060 科创50ETF 800份）
   - 用户只给部分信息：用已有信息完成分析，缺失字段标记"未知"，不反复追问
3. 生成统一市场快照（utils/data_router.py build_market_snapshot，只抓一次全模块复用）
   - ⚠ 若当天盘前/盘中已生成过 2026MMDD_index.json 等缓存（08:53/09:24 那种），收盘后必须先 rm data/2026MMDD_index.json amount sentiment sector market_value snapshot.json 再重建，否则快照是盘前数据（踩坑2026-08-03：快照显示科创50 +2.99%普涨，实际收盘 -5.08%）
4. 盘前计划验证：读取今日盘前报告 → 判断哪个情景命中 → 逐项验证观察条件 → 误差来源 → 校准落库（forecast_store）
5. 按报告结构生成 → 落盘（报告 md+json + 明日推演预测）

## 报告风格（2026-08-03 项目主理人定版，强制）
- 结论先行：开头 ╔══╗ 框线一句话总判断
- 数据一律表格化（markdown 表格）：指数/持仓/板块/三情景/盯防清单，禁止长段落堆数据、禁止原始 JSON
- emoji 规范：📊指数 🔴跌 🟡平 🟢涨 🔥流入 🧊流出 ✅正确 ⚠️风险 ❌错误 📋清单 ⏰观察 💡逻辑 🎯预测 📰消息 🔍分析；分节标题带 emoji
- 三情景表格：| 情景 | 概率 | 触发条件 | 应对 |，概率总和100%，附一句通俗解释（基准=最可能普通一天）
- 持仓表：现价/成本/浮亏%/止损/距止损%/动作
- 一段话≤3行，数字2-3位小数、统一单位

## 报告结构（按序输出）
1. 一句话结论（市场状态/是否适合交易/明日最重要观察）
2. 盘前计划验证（★闭环核心：盘前哪个情景真正发生？观察条件是否确认？仓位建议是否合适？误差来源？→ 校准预测历史）
3. 整体市场复盘（指数/量能/宽度/黄白线/活跃市值/情绪/主线/阶段定性）
4. 核心指标复盘（黄白线/砖型图/单针下20/换手率/活跃市值/B1节点/搬砖适用性，每项说明状态+变化+意义）
5. 行情多维复盘（技术/资金/情绪/板块/消息/海外——新闻先去重归类，只留重要信息）
6. 个人操作复盘（逐笔六项评分，见下）
7. 用户行为观察（单次记观察，不直接改画像；7天重复3次才更新 trader_profile.md）
8. 明日情景推演（三情景树，见下）→ 自动落盘 forecast_history（供次日盘前读取）
9. 今日经验沉淀

## 个人操作六项评分（评价决策不评价结果！）
每项0-5分，总分30。盈亏结果单独展示，不纳入决策质量总分。
- 方向前提：黄白线多头？空头买入=1分
- 战法匹配：有理由+节点信号=5；有理由=4；无理由(计划外)=0
- 入场位置：J≤20低位=5 / J≤60中位=3 / J>60追高=1；绿翻强红+1
- 仓位管理：未记录=1，记录金额=3（比例需人工确认）；⚠ETF金额=份数×单价（不是手数×100）
- 风险计划：止损止盈都有=5；只有止损=4；都没有=0
- 执行纪律：计划外=0；否则需人工确认按计划执行=3
- 铁律：盈利≠正确操作，亏损≠错误操作；盈亏主要来自判断/执行/随机波动要区分
- 针对问题给最多3条可执行改进措施

## 明日情景推演（不是猜涨跌，是条件树）
三情景：基准/强势/弱势，概率总和100%
每情景包含：概率/核心依据/触发条件/失效条件/对应仓位/次日重点观察指标
依据覆盖：黄白线/指数关键位/砖型图/市场宽度/成交量/活跃市值/情绪/板块主线/资金/政策新闻/美股/韩股/汇率商品
结尾输出：明日最重要3个观察指标 + 开盘需验证条件 + 何时降仓位 + 何时提高积极性 + 置信度
⚠ 未来函数禁令：预测只能使用生成时已公开数据（A股当日收盘✓、韩股当日✓、美股上一交易日✓、美股期指当前值✓；绝不能用未来数据）

## 报告模式
- 简单复盘：市场结论/核心指标/操作主要问题/明日三情景/观察重点
- 标准复盘：完整结构（默认）
- 深度复盘：+数据源对比/指标变化详情/逐笔评分明细/新闻影响链/海外传导
- 无操作：跳过逐笔评分，其余照常

## 推送规则（生成与推送解耦）
- 默认不推送！只有用户明确说「推送到钉钉」才调用推送
- 模糊表述不得解释为推送授权
- 「推送上一份复盘」=发缓存报告，不重新生成（utils/report_store.py load --type post_market）
- 支持语义：盘后复盘(不推)/简单复盘/深度复盘/复盘并推送/推送上一份

## 0AmV 自主计算+对账（2026-08-26 用户约定,每日必做）
- 每天盘后先用 `python3 utils/amv_predict.py predict` 自主计算当日 0AmV 全套字段(开/高/低/收/额/量/幅),预测值括号标注"(计算)"——用户有空补真实值,没空用计算版
- 每天执行 `python3 utils/amv_predict.py refit` 滚动重拟合系数(自动追加 data/reports/0AmV_拟合升级日志.md),实现公式持续升级
- 用户提供实际值后:补录 CSV(含OHLC/额量),算实时版与AR2两版误差%,追加 data/reports/0AmV_对账日志.md
- 公式参考:data/reports/0AmV公式拟合报告_2026-08-25.md;最新系数以 amv_predict.py refit 输出为准

## 数据源策略（字段级路由）
- 行情/日线：腾讯（自选小池）→mootdx兜底；批量用mootdx
- 财务/估值/新闻/选股：iFinD（受控额度2000次）
- 板块/情绪/北向：akshare新浪/乐咕
- 美股：iFinD/妙想；韩股KOSPI：akshare新浪(首尔综合指数)
- 每项数据保留 source + as_of；冲突时记录 selected_source + reason
- 禁止编造缺失数据，缺失标注"数据缺失"

## ⚠ 指标使用边界（强制，2026-08-01确认 + 08-02 ETF改版）
分层工具严格划分，禁止跨层乱用：
1. 大盘环境：只用【活跃市值】定仓位/是否出手；指数均线/涨跌家数/成交额辅助；不用BBI黄白线、砖型图做开仓否决
2. 板块/行业：只用【均线系统(20/60日)+成交量+相对强弱】；禁止板块砖型图、禁止板块BBI制定纪律
3. 交易标的：
   - 个股：【BBI黄白线】(空头禁开仓铁律) + 【砖型图】(B1/B2/B3买点) + 单针下20；所有买卖纪律只读个股自身图表
   - **ETF【2026-08-02改版】不用黄白线+红绿砖**（图形买点体系不适用，ETF本质=板块载体）：只用【均线MA20/MA60 + 量能】——均线多头(MA20>MA60)替代黄白线多头，放量(量能比≥1.2)替代砖型翻红，偏离MA20%替代偏离黄线%
研判流程：大盘活跃市值 → 板块均线 → 个股BBI+砖型图 / ETF均线+量能
禁止：①"指数跌破黄白线"作持仓操作核心依据 ②分析板块砖型图 ③拿指数/板块BBI当操作约束 ④对ETF用黄白线/砖型图/单针下20

## ⚠ 数据标注规范（2026-08-01）
- 区分【盘面定性结论(可靠)】和【价格/偏离%/止损位(推演估算)】
- 持仓成本/现价以用户提供为准，不得用模板数值冒充
- 未导入精确黄线坐标时，偏离黄线%、止损位标注【预估推演值，仅供参考，不可直接交易】
- 禁止自动生成脱离当前市价的止损价格——止损优先人工输入
